# 展项开发规范

> **规范级别：强制执行**
>
> 本规范适用于所有后续展项。首个生产展项是本规范的参考实现；除经确认的缺陷修复或明确批准的平台级改进外，不得修改已冻结展项。

## New Exhibit Checklist（新展项速查）

- [ ] 仅新增展项数据 `src/exhibits/data/<exhibitName>.ts` 和模型 `src/exhibits/models/<ExhibitName>Model.ts`（如确有必要，可增加经评审批准的展项专属资源，但不得复制控制器体系）。
- [ ] 定义完整的中文展项信息、部件、工艺步骤、技术成果、应用场景及有来源时的经济/环境指标。
- [ ] 为每个部件配置稳定 ID、中文名称、技术作用、说明、特征、对象引用及完整的常态/拆解/标签变换数据。
- [ ] 构建具有真实工业尺度感、工程辨识度和可交互分组的高性能程序化 Three.js 模型。
- [ ] 在展项模式中完成悬停、高亮、锚定标签、点击与信息查看；不得新增“部件查看”模式。
- [ ] 完成“拆解展示 / 恢复结构”、平滑动画、标签跟随、拆解态交互和离场自动复位。
- [ ] 完成工艺上一步/下一步/自动演示、关联部件高亮及轻量级三维流向表现。
- [ ] 完成结构化中文技术成果页、指标卡及指标/部件联动。
- [ ] 清理几何体、材质及克隆材质、临时网格、标签、流程对象、动画状态和事件监听器。
- [ ] 所有可见 UI 均为中文，操作区位于左下、操作指引位于右下，且无重复操作入口。
- [ ] 每一开发阶段分别提交 commit、创建 PR，并通过 `npm run typecheck`、`npm run build` 和 Vercel 视觉验证。
- [ ] 完整执行验收路径并通过，随后标记为 `FROZEN / V1.0`。

## 1. 目的与适用原则

本文件定义展项从数据建模、三维实现、交互与展示到验收冻结的统一标准。所有“必须”“不得”“应”均为开发与评审的约束条件：

1. 优先复用平台共享能力，保持不同展项的一致体验和维护边界。
2. 展项差异原则上通过**展项数据、模型实现、部件配置、工艺配置和技术成果配置**表达。
3. 共享框架仅在变更能够为**全部展项带来明确收益**时修改；变更须作为平台级改进单独评审。
4. 不得为单个展项复制、分叉或重建控制器系统。

## 2. 参考展项与冻结状态

**Reference Exhibit（参考展项）：**

高盐有机废水MVR蒸发分盐及资源化利用技术

**Status（状态）：**

`FROZEN / V1.0`

后续展项必须以现有 MVR 展项的数据组织、模型分组、交互接入、模式切换、资源清理和验收表现为参考实现。参考实现用于指导集成方式，不代表允许复制后再形成展项专属控制器。

## 3. 共享框架

以下模块属于平台共享、可复用基础设施：

| 模块 | 共享职责 |
| --- | --- |
| `ExhibitViewer` | 进入/离开展项、相机过渡、展项旋转与缩放，以及展厅状态恢复。 |
| `ExhibitShowcase` | 展项展示区域及展项级展示界面的统一承载。 |
| `ComponentInteractionManager` | 部件射线检测、悬停、选择、高亮、标签及部件信息交互。 |
| `ExplosionController` | 拆解状态、恢复状态、模式协调和拆解交互生命周期。 |
| `ExplosionAnimation` | 常态位置与拆解位置之间的平滑动画。 |
| `ProcessController` | 工艺步骤导航、自动演示、模式进入/退出和关联部件协调。 |
| `ProcessAnimation` | 工艺步骤切换与自动演示的时序和动画推进。 |
| `ProcessVisualizer` | 基于工艺路径的轻量级三维流向展示。 |
| `TechnologyController` | 技术成果模式、内容选择和三维联动协调。 |
| `TechnologyPanel` | 技术概览、优势、应用和指标等结构化内容展示。 |
| `TechnologyMetricCard` | 技术指标卡及其交互状态。 |
| `TechnologyHighlightController` | 技术优势/指标与相关三维部件之间的高亮联动。 |
| `ExhibitModeMenu` | 展项动作入口及不同展示模式间的统一切换。 |
| `ExhibitResourceManager` | 各模式临时对象、清理回调和资源释放的集中管理。 |

### 强制复用规则

- 未来展项**不得复制上述控制器**，不得创建诸如 `<ExhibitName>ProcessController`、`<ExhibitName>ExplosionController` 等平行系统。
- 若现有共享接口不能表达某项需求，应先验证能否通过展项数据、模型对象分组或现有配置字段实现。
- 只有对全部展项均有清晰、可验证收益的能力，才可提议修改共享框架；平台级变更必须验证现有冻结展项没有回归。
- 单一展项的特殊工艺、布局或内容不得成为污染共享控制器的理由，通常应封装于该展项的数据、模型、部件、流程或技术成果配置中。

## 4. 必需展项文件

每个新展项通常只需新增：

```text
src/exhibits/data/<exhibitName>.ts
src/exhibits/models/<ExhibitName>Model.ts
```

- 数据文件负责声明展项内容、部件配置、工艺配置和技术成果配置。
- 模型文件负责创建模型、可交互对象分组和必要的模型级资源管理。
- 命名必须明确、稳定，并与展项注册所使用的名称一致。
- 不得在展项目录下新建重复的交互、拆解、流程、技术成果或模式菜单控制器。

## 5. 展项定义要求

每个展项定义必须包含以下内容，并使用可审校的中文展示文案：

- `id`：全局唯一、稳定且不因展示文案调整而变化；
- 中文标题；
- 技术类别；
- 中文说明；
- 工艺概述；
- 核心特点；
- 部件列表；
- 工艺步骤；
- 技术概览；
- 技术优势；
- 技术指标；
- 应用场景；
- 在存在可靠来源数据时提供经济和环境指标。

数据应满足现有 `ExhibitDefinition` 契约。指标的数值、单位、适用条件和口径必须清晰；无可靠来源时不得编造数值，可省略不适用的经济/环境量化内容或采用经批准的定性描述。

## 6. 部件要求

每个可交互部件必须支持：

- 稳定且在展项内唯一的部件 ID；
- 中文部件名称；
- 技术作用；
- 中文说明；
- 核心特点；
- 可解析到模型对象的对象引用；
- 常态位置；
- 旋转信息；
- 拆解目标位置；
- 标签锚点。

部件 ID 是流程步骤、技术优势、指标卡和三维对象之间的关联键，一经进入验收阶段不得随意修改。对象引用必须对应可寻址的模型组。标签锚点应靠近目标部件、避免遮挡关键结构，并能随部件在拆解动画中同步移动。

## 7. 三维模型要求

模型必须遵守以下标准：

1. 除非另有明确批准的实现方案，使用程序化 Three.js 几何体构建。
2. 通过设备比例、管路关系、基座和辅助结构传达可信的工业尺度。
3. 保留可辨识的工程结构，使主要设备的形态与工艺作用一致。
4. 以浏览器实时性能为优先，不以不可感知的细节牺牲帧率、内存或加载时间。
5. 尽可能复用几何体和材质；相同构件优先共享资源或使用适合的实例化方案。
6. 避免不必要的面数、过密曲面分段、隐藏内部细节和高成本透明叠层。
7. 为所有交互部件提供独立、稳定、可寻址的 `Group`/`Object3D` 层级，并与部件 ID 建立明确映射。
8. 明确共享资源的所有权，避免在释放单个部件时提前销毁仍被其他对象使用的资源。

## 8. 部件交互标准

部件交互在展项模式中**始终可用**，不得创建独立的“部件查看”模式。用户必须能够：

- 悬停部件；
- 看到明确但不过度干扰的高亮反馈；
- 看到与部件绑定的锚定标签；
- 点击部件；
- 打开并阅读部件信息。

上述能力必须在常态和拆解态均保持工作。拖拽旋转与点击选择应正确区分，标签和命中区域不得停留在部件移动前的位置；模式切换或离开展项时必须清除残留悬停、选择和标签状态。

## 9. 拆解展示标准

每个支持拆解的展项必须提供：

- `拆解展示` 操作；
- 拆解后同一位置切换为 `恢复结构` 操作；
- 从常态到拆解态、从拆解态到常态的平滑动画；
- 随移动部件实时更新的标签；
- 拆解态下完整的悬停、点击和部件信息交互；
- 离开展项前的自动结构恢复。

动画应从对象当前状态连续过渡，避免跳变、穿插和重复触发造成的错位。恢复完成后，所有部件必须回到定义的常态位置和旋转，且不得遗留拆解态资源或控制状态。

## 10. 工艺展示标准

### 10.1 工艺步骤数据

每个工艺步骤应支持：

- 稳定且唯一的步骤 ID；
- 中文标题；
- 中文说明；
- 相关部件 ID 列表；
- 视觉状态（至少包含语义标签和颜色，可包含粒子速度等轻量参数）；
- 适用时提供三维工艺路径航点。

路径航点应按模型局部坐标定义，顺序与介质实际流向一致，并避免穿过不相关设备。所有关联部件 ID 必须能够解析到展项部件。

### 10.2 工艺模式能力

工艺模式必须支持：

- 上一步；
- 下一步；
- 自动演示及清晰的播放状态；
- 当前步骤关联部件高亮；
- 沿路径运动的轻量级三维流向可视化。

流程切换应清理上一阶段的视觉状态；自动演示结束、手动退出或离开展项时应停止计时与动画。除非经过明确的性能和产品审批，不得采用高成本的真实流体模拟；默认使用路径、粒子、线段、颜色或脉冲等低成本表达。

## 11. 技术成果标准

技术成果模式必须使用结构化中文信息呈现：

- 简洁的技术概览；
- 技术优势；
- 指标卡；
- 应用标签；
- 有可靠来源时的经济和环境指标。

技术成果不是长篇文章页面。文案应短、准、可扫描：概览说明价值，优势说明机制，指标卡突出数值、单位和必要注释，应用使用标签表达。具有 `relatedComponents` 的优势或指标必须能够联动高亮对应三维部件；清除选择或退出模式时同步清除高亮。

## 12. UI 标准

所有用户可见 UI 必须使用中文，包括标题、按钮、状态、提示、标签、指标、错误和空状态。

展项动作区通常只包含：

- `拆解展示` / `恢复结构`；
- `工艺流程`；
- `技术成果`；
- `返回展厅`。

布局要求：

- 展项动作控件位于**左下方**；
- 展项操作指引位于**右下方**；
- 同一个动作不得在多个面板中重复出现；
- 展厅导航指引与展项导航指引必须保持独立，不得同时混用或互相覆盖；
- 不得以“部件查看”按钮或模式重复已有的直接部件交互。

## 13. 资源生命周期

每个展项及每种模式都必须明确资源所有权，并在退出、切换或销毁时正确清理：

- 几何体；
- 材质；
- 为高亮或状态变化创建的克隆材质；
- 临时网格和其他临时 `Object3D`；
- DOM/CSS2D 标签；
- 工艺路径、粒子及其他流程可视化对象；
- 补间、计时器、自动播放和其他动画状态；
- 指针、滚轮、键盘及自定义事件监听器。

应在适用处使用 `ExhibitResourceManager` 追踪按模式创建的临时对象与清理回调。清理操作应可重复调用且结果一致；不得释放仍由共享对象使用的资源，也不得在反复进入展项后累积对象、监听器或动画。离开展项后再进入，必须获得与首次进入一致的初始状态。

## 14. 强制验收流程

任何展项只有完整通过以下端到端路径后，才可视为完成：

```text
展厅
→ 热点
→ 进入展项
→ 旋转
→ 缩放
→ 部件悬停
→ 部件点击
→ 拆解
→ 拆解态检查部件
→ 恢复
→ 工艺模式
→ 自动工艺演示
→ 技术成果模式
→ 指标/部件联动
→ 返回展厅
→ 再次进入展项
```

验收人员应同时确认：各阶段中文 UI 正确、标签与高亮无残留、模式间状态互斥、返回后展厅导航恢复、重进后模型和控制器回到初始状态。任一步骤失败、出现控制台错误、资源持续增长或重进状态异常，均不得通过验收。

## 15. 冻结策略

展项通过最终验收后必须：

1. 标记为 `FROZEN / V1.0`；
2. 记录验收版本及结果；
3. 停止功能性或表现性调整。

冻结后仅允许两类变更：

- 修复已复现并确认的缺陷；
- 实施经过明确批准、对平台全部展项有益的改进。

任何冻结后变更都必须说明原因、影响面和回归范围，并重新执行完整验收流程。不得借新展项开发之机顺带重构或调整已冻结的 MVR 参考展项。

## 16. 开发工作流

每个新展项严格按以下阶段推进：

| 阶段 | 目标 | 阶段完成条件 |
| --- | --- | --- |
| Phase A | 技术数据架构 | 定义、部件、流程、技术成果及来源口径完成评审。 |
| Phase B | 程序化三维模型 | 工业尺度、工程结构、对象分组和性能达到要求。 |
| Phase C | 部件交互 | 悬停、高亮、标签、点击和信息面板完整可用。 |
| Phase D | 拆解展示 | 拆解/恢复动画、标签跟随、拆解态交互和自动恢复通过。 |
| Phase E | 工艺可视化 | 步骤导航、自动演示、部件高亮和轻量流向展示通过。 |
| Phase F | 技术成果展示 | 概览、优势、指标卡、应用、经济/环境指标及部件联动通过。 |
| Phase G | 最终验收与冻结 | 完整验收路径通过，版本标记为冻结。 |

### 每阶段门禁

每个阶段都必须独立完成以下事项后，方可进入下一阶段：

1. 创建范围清晰的 commit；
2. 创建对应 PR，并说明阶段目标、变更内容和验证结果；
3. 运行并通过 `npm run typecheck`；
4. 运行并通过 `npm run build`；
5. 在 Vercel 部署中进行视觉验证，确认布局、模型、交互和响应式表现符合该阶段要求。

不得把多个尚未验证的阶段合并推进，也不得以本地编译通过替代 Vercel 视觉验证。Phase G 完成后执行冻结策略；后续展项从 Phase A 重新开始，不得复制上一展项的专属实现。
